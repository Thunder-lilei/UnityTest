## 1. 项目概述

| 项 | 内容 |
|---|---|
| **名称** | Wuxia |
| **路径** | `C:\Learn\UnityTest\Wuxia\` |
| **引擎** | Tuanjie 1.9.3 |

## 2. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 输入 | Input System（新） | 可扩展、事件驱动、学习价值高 |
| 渲染 | URP | VFX Graph 兼容好、性能适中 |
| 逻辑 | C# → 中后期 xLua | 先 C# 跑通，预留 Lua 接入点 |
| 特效 | VFX Graph（自研） | 前期用临时素材跑通链路，后期亲手替换 |
| 镜头 | Cinemachine | 后期做展示用，前期简单跟随 |
| 动画 | Animator + Animation Event | 标准方案，动画事件驱动特效触发 |
| 角色 | Mixamo 默认角色 | 非展示重点，只需能播动画的人形骨架 |
| 音效 | AI 生成 | SFX + BGM 均使用 AI 生成 |

## 3. 架构设计

### 3.1 目录结构

```
Assets/
├── Scripts/
│   ├── Core/           # 框架层：事件系统、接口定义
│   ├── Player/         # 角色控制、移动、输入响应
│   ├── Combat/         # 攻击系统：配置、管理器、接口
│   ├── VFX/            # VFX 触发与生命周期管理
│   ├── Camera/         # 镜头控制（后期）
│   ├── AI/             # 敌人 AI（后期）
│   └── Lua/            # xLua 接入与桥接层（中后期）
├── Data/
│   └── Attacks/        # 攻击配置 ScriptableObjects
├── Prefabs/
│   ├── Player/
│   ├── VFX/            # VFX 预制体
│   └── Environment/
├── Scenes/
├── Settings/           # URP 配置、Input Actions 配置
└── Model/              # 模型资源（FBX/贴图，动画与模型同目录）
    ├── Characters/      # 角色（模型+动画）

    ├── Buildings/       # 建筑（亭子/房屋/城门）
    └── Props/          # 道具装饰（灯笼/栅栏/石阶）
```

### 3.2 可扩展攻击系统（核心设计）

**思路：每个攻击 = 一份配置 + 一个 VFX 预制体，加新攻击不改代码，只加配置。**

```
┌─────────────────────────────────────────────┐
│              AttackConfig (SO)               │
│  attackName: "刀光斩"                        │
│  animationTrigger: "Attack_Slash"             │
│  vfxPrefab: SlashVFX.prefab                  │
│  vfxSpawnOffset: (0, 1, 1.5)                 │
│  vfxSpawnDelay: 0.15s    ← 动画到中段才出特效  │
│  cooldown: 0.8s                              │
└──────────────────┬──────────────────────────┘
                   │ 被引用
                   ▼
┌─────────────────────────────────────────────┐
│           AttackManager (MonoBehaviour)      │
│  - 持有所有 AttackConfig 列表                 │
│  - TriggerAttack(name) → 查配置→播动画        │
│  - 动画事件回调 → 生成VFX → 进入冷却           │
└─────────────────────────────────────────────┘
```

**加新攻击动作的流程：**
1. 做好 VFX 预制体
2. 右键创建 AttackConfig SO，填参数
3. 在 AttackManager 列表里加入引用
4. 完成——零代码修改

### 3.3 Lua 预留接入点

前期不引入 xLua，但代码结构按以下原则设计，让后期迁移平滑：

| 接入点 | 设计方式 | 后期 Lua 替换什么 |
|--------|----------|-------------------|
| **伤害计算** | `IDamageCalculator` 接口 | Lua 脚本重写伤害公式 |
| **技能逻辑** | `ISkillLogic` 接口 | Lua 控制技能特殊效果 |
| **AI 行为** | 事件驱动 + 状态机 | Lua 替换状态切换逻辑 |
| **配置热更** | ScriptableObject 数据 | Lua Table 做运行时覆盖 |

**核心原则**：关键逻辑走接口，不写死在 MonoBehaviour 里。

### 3.4 输入系统设计

```
Input Actions 配置文件 (WuxiaInputActions.inputactions)
├── Movement Action Map
│   ├── Move    (Vector2)  ← WASD / 左摇杆
│   ├── Sprint  (Button)   ← Shift / 右摇杆按下
│   └── Jump    (Button)   ← Space / 手柄A
├── Combat Action Map
│   ├── Attack1 (Button)   ← 鼠标左键 / 手柄X
│   ├── Attack2 (Button)   ← 鼠标右键 / 手柄Y
│   └── Dodge   (Button)   ← Q / 手柄B
└── Camera Action Map
    └── Look     (Vector2)  ← 鼠标移动 / 右摇杆
```

代码端通过 C# 事件转发，输入与逻辑完全解耦。

## 4. 场景设计

| 项 | 内容 |
|---|---|
| **主题** | 竹林演武场 |
| **大小** | ~30m × 30m 活动区域 |
| **光照** | 白天，方向光模拟日光，柔和阴影 |
| **氛围** | 白天竹林，光影斑驳 |
| **后期** | URP Post Processing：色彩校正、景深、暗角（轻微）|
| **元素** | 竹林环绕、石板地面、几块山石点缀 |

## 5. 角色与动画

| 项 | 内容 |
|---|---|
| **角色** | Mixamo 默认人形角色 |
| **必需动画** | Idle / Walk / Run / Jump |
| **攻击动画** | 按需增加（挥剑、出拳等，从 Mixamo 获取） |
| **Animator** | 状态机 + 混合树（走跑用 Blend Tree） |
| **动画事件** | 在攻击动画关键帧打 Event，触发 VFX 生成 |

## 6. 性能预算

| 项 | 目标 |
|---|---|
| 帧率 | 60 FPS |
| VFX 粒子上限 | 单个特效 < 5000 粒子，同时活跃 < 20000 |
| Draw Call | < 200 |
| 压力来源 | 复杂 VFX 特效（如万剑归宗），不靠增加模型面数 |

## 7. 开发阶段规划

| 阶段 | 内容 | 产出 |
|------|------|------|
| **P0 · 基建** | 建项目、URP 配置、Input Actions、目录结构 | 空工程能跑 |
| **P1 · 移动** | CharacterController + 走/跑/跳 + 简单摄像机跟随 | 角色能在场景里跑动 |
| **P2 · 攻击骨架** | AttackManager + AttackConfig + 临时 VFX 触发 | 按键能出特效 |
| **P3 · 自研 VFX** | VFX Graph 制作刀光/拳风，替换临时素材 | 视觉达标 |
| **P4 · 音效** | AI 生成 SFX + BGM，攻击/脚步/跳跃音效系统 | 听觉达标 |
| **P5 · 敌人系统** | 简单 AI + 受击反馈 | 可打靶 |
| **P6 · 打击反馈** | 顿帧、屏幕震动、受击闪白、残影拖尾 | 手感达标 |
| **P7 · 场景打磨** | 竹林场景 + 灯光 + 后期处理 | 氛围达标 |
| **P8 · VFX 极限与性能优化** | 万剑归宗级复杂特效 + Profiler 性能分析与优化 | 性能达标 |
| **P9 · 镜头展示** | Cinemachine 运镜 + 录制 | 可展示 |
| **P10 · Lua 接入** | xLua 框架 + 部分逻辑迁移 | 热更链路跑通 |

### 7.1 打击反馈细节（P6）

| 技巧 | 效果 | 实现方式 |
|------|------|---------|
| **Hit Stop（顿帧）** | 命中瞬间世界暂停 0.02-0.05s | Time.timeScale 短暂归零 |
| **屏幕震动** | 攻击命中时镜头微震 | Cinemachine Impulse |
| **受击闪白** | 敌人被击中瞬间变白 | Shader 或材质替换 |
| **粒子拖尾** | 快速移动/攻击时留下残影 | VFX Graph Trail |

### 7.3 VFX 极限与性能优化（P8）

| 项 | 内容 |
|---|---|
| **目标** | 用极端 VFX 场景学习 Unity 性能分析工具 |
| **压测特效** | 万剑归宗——数千剑影 + 拖尾 + 粒子 + 光效 |
| **学习工具** | Profiler、Frame Debugger、VFX Graph 性能面板 |
| **优化方向** | 粒子数控制、LOD、GPU Instancing、VFX Graph Burst |
| **不做的事** | 不靠堆模型面数制造压力 |

## 8. 设计决策记录

| 决策 | 理由 |
|------|------|
| 不做连招系统 | 前期聚焦单次攻击手感，连招调试依赖实际效果反馈，延后无损失 |
| Mixamo 默认角色 | 角色非展示重点，只需能播动画的人形骨架 |
| 不固定攻击数量 | 可扩展架构（SO 配置驱动），加新攻击零代码修改 |
| 前期纯 C#，预留 Lua 接入点 | 先跑通逻辑，关键逻辑走接口，后期 xLua 迁移平滑 |
| 场景打磨放在 P7 | 场景非主要重心，收尾展示阶段才需要关注 |
| 性能压力从 VFX 入手 | 符合学习兴趣方向，不靠增加模型面数 |
| 单 main 分支 | 作者独立开发，最终用户只关注最终版本 |
