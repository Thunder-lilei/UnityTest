# P1 · 移动

> 依赖：P0 · 状态：部分完成（待用户完成输入和相机脚本）

## 目标

角色能在场景里自由跑动、跳跃。

## 任务拆解

### 1. 角色控制器选型

#### 技术选型

| 项 | 内容 |
|---|---|
| **选择** | Rigidbody（物理驱动） |
| **原因** | 俯视角动作游戏，不需要精确的台阶/坡度处理，物理驱动移动更自然，被击退等效果天然支持 |
| **替代方案①** | CharacterController |
| **不选①** | 适合第三人称精确控制，俯视角不需要那么精确，且被击退需手动实现 |
| **替代方案②** | 纯 Transform 移动 |
| **不选②** | 无物理碰撞响应，不符合动作游戏需求 |

#### 配置

- **Rigidbody**:
  - `constraints = FreezeRotation`：冻结三轴旋转。**原因**：Rigidbody 默认会受力产生物理旋转，角色被碰到后会像物体一样翻滚倒地，这在动作游戏中不可接受。冻结旋转后角色始终直立，朝向由代码控制。
  - `collisionDetectionMode = Continuous`：连续碰撞检测。**原因**：默认的 Discrete（离散检测）在角色高速移动时可能穿透墙壁——物理引擎每帧只在固定时刻采样位置，如果一帧内移动距离大于碰撞体厚度，就会"穿过去"。Continuous 模式在帧间做插值检测，代价是略微增加 CPU 开销，但对动作游戏是必须的。
- **CapsuleCollider**: height=0.72, radius=0.14, center=(0, 0.36, 0)
  - 这些数值是 **Local Space（局部空间）**。**原因**：Player GameObject 的 transform.scale=2.5，Collider 的尺寸是相对于缩放后的物体而言的。实际世界尺寸 = local值 × scale，即 height=0.72×2.5=1.8m（成年人身高），radius=0.14×2.5=0.35m，center.y=0.36×2.5=0.9m（角色腰部）。
  - 用 **Capsule** 而非 Box：胶囊体的圆弧底面在台阶和斜坡上滑动更自然，不会卡住棱角。
- **Animator**:
  - `applyRootMotion = false`：**原因**：Root Motion 是让动画驱动角色位移（如跑步动画本身包含向前移动的位移数据）。我们选择由 Rigidbody 控制位移，如果同时开着 Root Motion，动画和物理会争夺位移控制权，导致角色抖动或漂移。关掉后，动画只负责外观（手脚摆动），位移完全由代码的 `velocity` 控制。

#### 手动操作

1. 选中 Player GameObject
2. Add Component → Rigidbody
3. Inspector 中 Rigidbody → Constraints → 勾选 Freeze Rotation X/Y/Z
4. Add Component → Capsule Collider
5. 设置 Collider 参数（见上方配置）
6. Animator 组件 → Apply Root Motion 取消勾选

   - Walk / Walking
   - Run / Running
   - Jump Start / Jump Up
4. 每个 FBX 下载时 Format 选 FBX，Skin 选 Without Skin（只导出动画，不含模型）

#### 步骤 3.2：编写 InputReader 脚本

**文件位置：** `Assets/Scripts/Player/InputReader.cs`

**职责：** 读取 Input System 输入 → 调用 `PlayerController` 的公共方法

**完整代码：**

```csharp
using UnityEngine;
using UnityEngine.InputSystem;

namespace Wuxia.Player
{
    /// <summary>
    /// 输入读取器：将 Input System 事件转发给 PlayerController。
    /// 挂载在 Player GameObject 上，与 PlayerController 同级。
    /// </summary>
    [RequireComponent(typeof(PlayerController))]
    public class InputReader : MonoBehaviour
    {
        // P0 生成的 C# Wrapper 实例
        private WuxiaInputActions _input;

        // 缓存 PlayerController 引用，避免每帧 GetComponent
        private PlayerController _playerController;

        private void Awake()
        {
            _playerController = GetComponent<PlayerController>();
            _input = new WuxiaInputActions();
        }

        private void OnEnable()
        {
            _input.Enable();

            // 注册输入事件回调
            // performed: 输入值变化时触发
            // canceled: 输入停止时触发（如松开按键）
            _input.Movement.Move.performed += OnMove;
            _input.Movement.Move.canceled += OnMove;
            _input.Movement.Sprint.performed += OnSprint;
            _input.Movement.Sprint.canceled += OnSprint;
            _input.Movement.Jump.performed += OnJump;
        }

        private void OnDisable()
        {
            // 注销回调，防止 GameObject 禁用后仍收到输入
            _input.Movement.Move.performed -= OnMove;
            _input.Movement.Move.canceled -= OnMove;
            _input.Movement.Sprint.performed -= OnSprint;
            _input.Movement.Sprint.canceled -= OnSprint;
            _input.Movement.Jump.performed -= OnJump;

            _input.Disable();
        }

        private void OnDestroy()
        {
            _input?.Dispose();
        }

        /// <summary>
        /// 移动输入回调。performed 时有输入值，canceled 时值为零向量。
        /// </summary>
        private void OnMove(InputAction.CallbackContext context)
        {
            _playerController.SetMoveInput(context.ReadValue<Vector2>());
        }

        /// <summary>
        /// 冲刺输入回调。performed = 按下 Shift，canceled = 松开 Shift。
        /// </summary>
        private void OnSprint(InputAction.CallbackContext context)
        {
            _playerController.SetSprint(context.ReadValueAsButton());
        }

        /// <summary>
        /// 跳跃输入回调。只在按键按下瞬间触发一次（performed）。
        /// </summary>
        private void OnJump(InputAction.CallbackContext context)
        {
            _playerController.Jump();
        }
    }
}
```

**代码说明：**

| 代码 | 为什么这样写 |
|---|---|
| `[RequireComponent(typeof(PlayerController))]` | 确保同一个 GameObject 上必须有 PlayerController，否则报错。**原因**：InputReader 的职责是把输入转发给 PlayerController，如果 PlayerController 不存在，转发就会空引用。用 Attribute 约束比运行时报错更早发现问题 |
| `_input = new WuxiaInputActions()` | 实例化 P0 生成的 C# Wrapper。**原因**：`.inputactions` 文件是数据资产，代码里不能直接调用它，需要实例化为运行时对象才能读取输入 |
| `performed` / `canceled` 事件 | Input System 的事件驱动模式，按键按下→performed，松开→canceled。**原因**：相比旧 Input Manager 的 `Input.GetKey()` 每帧轮询，事件驱动只在输入变化时触发回调，性能更好且逻辑更清晰 |
| `OnEnable` 注册 / `OnDisable` 注销 | 配对使用，防止对象禁用后仍收到输入导致空引用。**原因**：如果 GameObject 被 SetActive(false) 但 InputAction 仍在监听，回调会尝试访问已禁用的组件，导致 NullReferenceException |
| `context.ReadValue<Vector2>()` | 读取 WASD 的 Vector2 值（x=左右, y=前后）。**原因**：Move Action 在 P0 配置为 Value 类型 + 2DVector 复合绑定，WASD 四个键自动合成为一个二维向量，比逐个 `Input.GetKey(KeyCode.W)` 拼接简洁得多 |
| `context.ReadValueAsButton()` | 读取 Shift 按键的布尔值（按下=true, 松开=false）。**原因**：Sprint Action 在 P0 配置为 Button 类型，Button 类型用 ReadValueAsButton() 返回布尔值，比 `ReadValue<float>() > 0` 更直观 |
| `OnDestroy` 中 Dispose | 释放 InputSystem 资源，防止内存泄漏。**原因**：WuxiaInputActions 实现了 IDisposable，C# 的 GC 不会立即释放它持有的非托管资源，需要显式释放 |
| Move 同时注册 performed 和 canceled | **原因**：Move 是持续性输入（按住 W 持续前进），松开 W 时需要把输入归零。如果只注册 performed，松开按键后角色会继续移动——因为最后一次 performed 的值还在缓存里，不会被清除 |

#### 步骤 4.1：编写 CameraFollow 脚本

**文件位置：** `Assets/Scripts/Camera/CameraFollow.cs`

**完整代码：**

```csharp
using UnityEngine;

namespace Wuxia.Camera
{
    /// <summary>
    /// 俯视角摄像机跟随：固定角度，平滑跟随玩家位置。
    /// 挂载到 Main Camera 上。
    /// </summary>
    public class CameraFollow : MonoBehaviour
    {
        [Header("跟随目标")]
        [Tooltip("玩家角色的 Transform")]
        [SerializeField] private Transform target;

        [Header("摄像机偏移")]
        [Tooltip("相对于玩家位置的偏移量。Y=高度，Z=后退距离，决定俯视角度")]
        [SerializeField] private Vector3 offset = new Vector3(0f, 15f, -10f);

        [Header("平滑参数")]
        [Tooltip("跟随速度，值越大跟随越紧（0-1，建议 0.05-0.2）")]
        [SerializeField] private float smoothSpeed = 0.1f;

        private void LateUpdate()
        {
            if (target == null) return;

            // 计算目标位置 = 玩家位置 + 偏移
            Vector3 desiredPosition = target.position + offset;

            // Lerp 平滑插值：从当前位置逐步移向目标位置
            transform.position = Vector3.Lerp(transform.position, desiredPosition, smoothSpeed);

            // 摄像机始终看向玩家
            transform.LookAt(target);
        }

        /// <summary>
        /// 运行时切换跟随目标（可选功能）。
        /// </summary>
        public void SetTarget(Transform newTarget)
        {
            target = newTarget;
        }
    }
}
```

**代码说明：**

| 代码 | 为什么这样写 |
|---|---|
| `LateUpdate` | 在所有 Update/FixedUpdate 之后执行，确保玩家位置已更新完毕再移动相机。**原因**：如果在 FixedUpdate 中移动相机，玩家 Rigidbody 也刚在 FixedUpdate 中更新位置，两个执行顺序不确定，可能导致相机跟随的是"上一帧"的玩家位置，产生肉眼可见的抖动。LateUpdate 保证在所有物理和逻辑更新之后才动相机 |
| `Vector3.Lerp(current, target, t)` | 线性插值，t=0 不动，t=1 瞬间到位，0.1 表示每帧追近 10%。**原因**：如果直接 `transform.position = desiredPosition`，相机会死板地贴在玩家头上，没有任何缓冲感。Lerp 让相机"追"玩家，产生自然的平滑跟随效果 |
| `transform.LookAt(target)` | 摄像机始终朝向玩家，offset 决定俯视角度。**原因**：如果不加 LookAt，相机会保持初始朝向，当玩家移动到相机下方时就会看不见角色。LookAt 确保无论玩家在哪，相机都对着他 |
| `offset = (0, 15, -10)` | Y=15 高度，Z=-10 后退，形成约 56° 俯视角。**原因**：Y 和 Z 的比例决定了俯视角度。Y 越大角度越陡（越像正上方），Z 越大角度越低（越像平视）。这个值能同时看到角色全身和前方足够远的地面，方便战斗时观察敌人 |
| `smoothSpeed` 0-1 范围 | 不用 Time.deltaTime 是因为 Lerp 的第三参数本身就是「完成比例」。**原因**：Lerp(a, b, t) 的数学本质是 `a + (b-a)*t`，t=0.1 意味着每帧把剩余距离缩短 10%，这是一个几何级数衰减，天然具有帧率无关性——不管 30fps 还是 144fps，视觉上跟随速度一致。而如果用 `t = smoothSpeed * Time.deltaTime`，在高帧率时 t 会很小（跟随慢），低帧率时 t 会很大（跟随快且抖动） |

**偏移量与俯视角度的关系：**

| offset | 俯视角度 | 效果 |
|---|---|---|
| (0, 20, 0) | 90° | 纯俯视（正上方往下看） |
| (0, 15, -10) | 56° | 斜俯视（推荐，能看到角色全身和前方地面） |
| (0, 10, -15) | 34° | 低角度斜视（更像第三人称） |

### 5. AnimatorController

#### 技术选型

| 项 | 内容 |
|---|---|
| **选择** | 1D Blend Tree + 状态机 |
| **原因** | 走跑混合只需一个 Speed 参数，1D 足够；跳跃用 Trigger 触发状态切换 |
| **替代方案** | 2D Blend Tree |
| **不选** | 2D 需要两个参数（如 Speed + Direction），俯视角移动不需要方向混合动画 |

#### 参数

| 参数名 | 类型 | 用途 |
|---|---|---|
| Speed | Float | 0=Idle, 0.5=Walk, 1=Run |
| IsGrounded | Bool | 是否在地面 |
| JumpTrigger | Trigger | 触发跳跃 |

#### 状态结构

```
Any State ──JumpTrigger──→ Jump
                              ↓ (IsGrounded=true, exitTime=0.7)
Idle ←──Speed<0.01──→ WalkRun (1D Blend Tree: Idle/Walk/Run)
```

**状态转换设计说明：**

| 转换 | 条件 | 原因 |
|---|---|---|
| Any State → Jump | JumpTrigger | 用 Any State 而非从 Idle/WalkRun 分别连到 Jump。**原因**：玩家可能在走、跑、站立时跳，如果从每个状态都连一条线到 Jump 会有 3 条重复转换，Any State 一条线搞定 |
| Jump → Idle | IsGrounded=true, exitTime=0.7 | exitTime=0.7 表示跳跃动画播放到 70% 才允许转换。**原因**：跳跃动画有起跳→空中→落地全过程，如果在动画刚播放就回到 Idle，视觉上会突然切掉。0.7 让起跳动作播放完再回到待机。同时加 IsGrounded=true 条件确保确实落地了才切回 |
| Idle → WalkRun | Speed > 0.01 | 不用 Speed > 0 而用 0.01。**原因**：摇杆输入有微小漂移（死区），手指离开摇杆后 Vector2 不会精确归零，可能是 (0.001, 0.002)。0.01 阈值过滤掉这种漂移，避免角色微微抖动 |
| WalkRun → Idle | Speed < 0.01 | 对称设计，停止移动时切回待机 |
| `hasExitTime = false`（Idle↔WalkRun） | — | **原因**：走跑切换需要即时响应，不等动画播放完。如果 hasExitTime=true，必须等当前动画播完才切换，按住方向键后角色会先放完一个完整的 Idle 循环才走，手感很迟钝 |

#### 手动操作

1. 创建 AnimatorController：Assets 右键 → Create → Animator Controller → 命名 PlayerAnimator
2. 双击打开 Animator 窗口
3. Parameters 标签 → 添加 3 个参数（Speed Float, IsGrounded Bool, JumpTrigger Trigger）
4. 创建 3 个 State：Idle, WalkRun, Jump
5. Idle 状态 → Motion 设为 Mixamo Idle 动画
6. WalkRun 状态 → 双击创建 Blend Tree → 1D, parameter=Speed → 添加 Idle(0), Walk(0.5), Run(1)
7. Jump 状态 → Motion 设为 Mixamo Jump 动画
8. 设置 Transitions（见上方状态结构图）

### 6. 场景搭建

#### 执行步骤

- 创建 Plane 作为地面，scale=(3,1,3) 即 30×30 单位
  - **原因**：Unity 默认 Plane 是 10×10 单位（1 单位 = 1 米），scale=3 放大到 30×30 米，给俯视角动作游戏足够空间移动。设计文档中场景活动区域是 30m×30m。
- 角色放置在 (0, 0.1, 0)
  - **Y=0.1 而非 0 的原因**：角色 CapsuleCollider 底部到原点有微小间距，放 Y=0 可以让角色脚底刚好贴地面，但物理引擎在角色脚底与地面完全接触时有时会产生微小弹跳。Y=0.1 把角色抬高一点点，让它自然落下贴地，消除初始抖动。

#### 手动操作

1. GameObject → 3D Object → Plane
2. Inspector → Transform → Scale = (3, 1, 3)
3. 将 Mixamo 角色 Prefab 拖入场景
