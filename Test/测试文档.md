## 4. 如何运行测试

1. 打开 Window → General → Test Runner
2. 选择 EditMode 标签
3. 点击 Run All


## 6. 测试设计原则

1. **测试纯逻辑优先**: 优先测试不依赖 Unity 生命周期的逻辑（EnemyData 数据验证）
2. **组件测试用 AddComponent**: EditMode 下可通过 AddComponent 创建 MonoBehaviour 实例
3. **每个测试独立**: SetUp/TearDown 确保测试间无状态污染
4. **命名规范**: MethodName_Condition_ExpectedResult

## 7. 测试用例创建步骤

### 7.1 前置条件：程序集定义文件

测试脚本不能直接放在 `Assets/Scripts/` 中和普通脚本混在一起，需要独立的程序集。项目中已有两个 asmdef 文件：

**`Assets/Scripts/Game.asmdef`** — 主程序集，包含所有游戏脚本：

```json
{
    "name": "Game",
    "rootNamespace": "Game",
    "references": [
        "Unity.RenderPipelines.Universal.Runtime",
        "Unity.TextMeshPro",
        "Unity.VisualEffectGraph.Runtime",
        "Unity.AI.Navigation"
    ],
    "includePlatforms": [],
    "excludePlatforms": [],
    "autoReferenced": true
}
```

**`Assets/Tests/Tests.asmdef`** — 测试程序集，仅 Editor 平台，引用主程序集和 NUnit：

```json
{
    "name": "Tests",
    "rootNamespace": "Game.Tests",
    "references": ["Game"],
    "includePlatforms": ["Editor"],
    "precompiledReferences": ["nunit.framework.dll"],
    "defineConstraints": ["UNITY_INCLUDE_TESTS"],
    "autoReferenced": false
}
```

> **关键点**：`references: ["Game"]` 让测试程序集能访问主程序集中的类；`includePlatforms: ["Editor"]` 限制测试只在编辑器运行不进打包；`precompiledReferences: ["nunit.framework.dll"]` 引入 NUnit 断言库。

### 7.2 创建测试脚本

1. 在 `Assets/Tests/` 目录下右键 → Create → C# Script
2. 命名规范：`XxxTests.cs`（如 `HealthBarTests.cs`）
3. 编写测试代码：

```csharp
using NUnit.Framework;          // 引入 NUnit 断言库
using UnityEngine;
using Game.UI;                    // 引入被测类所在命名空间

namespace Game.Tests
{
    public class HealthBarTests   // 不继承 MonoBehaviour
    {
        private GameObject go;
        private HealthBar healthBar;

        [SetUp]                    // 每个测试方法前执行（替代 Start）
        public void Setup()
        {
            go = new GameObject("Player");
            healthBar = go.AddComponent<HealthBar>();
            healthBar.maxHealth = 100f;

            // EditMode 不会调用 Start()，需手动初始化 private 字段
            var field = typeof(HealthBar).GetField("currentHealth",
                System.Reflection.BindingFlags.NonPublic | System.Reflection.BindingFlags.Instance);
            field.SetValue(healthBar, 100f);
        }

        [TearDown]                 // 每个测试方法后执行（清理）
        public void Teardown()
        {
            Object.DestroyImmediate(go);
        }

        [Test]                     // 标记为测试方法，Test Runner 自动发现
        public void TakeDamage_ToZero_IsDead()   // 命名：方法_条件_期望结果
        {
            healthBar.TakeDamage(100f);
            Assert.IsTrue(healthBar.IsDead(), "100HP 受 100 伤害应死亡");
        }
    }
}
```

### 7.3 测试脚本的常用断言

| 断言方法 | 用途 | 示例 |
|---------|------|------|
| `Assert.AreEqual(expected, actual)` | 相等 | `Assert.AreEqual(80, hp)` |
| `Assert.IsTrue(condition)` | 为 true | `Assert.IsTrue(hp.IsDead())` |
| `Assert.IsFalse(condition)` | 为 false | `Assert.IsFalse(hp.IsFull())` |
| `Assert.IsNotNull(obj)` | 非空 | `Assert.IsNotNull(spawned)`` |
| `Assert.IsNull(obj)` | 为空 | `Assert.IsNull(result)` |
| `Assert.AreSame(a, b)` | 同一引用 | `Assert.AreSame(obj1, obj2)` |
| `Assert.Pass(message)` | 直接通过 | `Assert.Pass("执行无异常")` |
| `Assert.Fail(message)` | 直接失败 | `Assert.Fail("不应到达此处")` |

### 7.4 注意事项

| 注意点 | 原因 | 解决方案 |
|--------|------|---------|
| `Start()` 不会被调用 | EditMode 不执行 MonoBehaviour 生命周期 | 用 `[SetUp]` + 反射手动初始化 private 字段 |
| `Update()` 不会执行 | 同上 | 测试纯逻辑方法，不依赖帧循环 |
| `AudioManager.Instance` 为 null | 测试环境无场景单例 | 用 `?.` 空条件运算符避免 NPE |
| `GetComponent<T>()` 可能返回 null | 测试环境无完整组件链 | 测试前手动 `AddComponent` 或用反射 |
| 普通脚本加 `[Test]` 不生效 | 无 NUnit 引用 + 无 asmdef 限制 | 测试必须放在 Tests 程序集中 |
