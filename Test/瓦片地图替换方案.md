# 地面瓦片地图替换方案

## 1. 目标

将当前单一纯色 Ground（Plane, scale 12×12 ≈ 120×120 单位）替换为多地形 3D 瓦片地面，实现**地形多样性**：草地 + 河流 + 石子路三种区域，增加视觉层次和玩法维度（河流作为天然屏障影响敌人寻路路线）。

## 2. 技术路线

```
创建 3D Quad Prefab → 创建 RuleTile 资产（Default GameObject = Quad Prefab）→ 用 Tilemap 画笔画布局 → NavMesh 烘焙 → 完成
```

- **RuleTile**：Unity 2D Tilemap 系统的扩展，支持根据邻接关系自动选择瓦片变体
- **Default GameObject**：RuleTile 内置字段，设置后画笔涂格子时自动实例化对应的 3D Quad Prefab，无需任何转换脚本
- **Tilemap 永久保留**：不删除，后续可随时修改瓦片布局，甚至运行时动态修改
- **零转换脚本**：画完即完成，无需编辑器菜单工具

## 3. 瓦片设计

### 3.1 地形类型

| 地形 | 颜色 | 色值 (RGB) | 可行走 | Collider |
|---|---|---|---|---|
| 草地 | 草绿 | (0.3, 0.6, 0.25) | ✅ | ✅ MeshCollider |
| 石子路 | 灰棕 | (0.5, 0.45, 0.4) | ✅ | ✅ MeshCollider |
| 河流 | 水蓝 | (0.2, 0.45, 0.7) | ❌ | ❌ 无 |

### 3.2 瓦片尺寸

| 参数 | 值 | 说明 |
|---|---|---|
| 每片大小 | 10×10 单位 | Quad 默认 1×1，scale = 10 |
| 网格规模 | 12×12 = 144 片 | 覆盖 120×120 单位，与原 Ground 一致 |
| Quad 旋转 | Euler(90, 0, 0) | 平铺朝上 |
| Quad 位置 Y | 0 | 贴地 |

### 3.3 布局规则（示意）

```
            石子路（边缘装饰带）
        ┌───────────────────────────┐
        │ 草地  草地  草地  草地  草地 │
        │ 草地  ──石子路──  草地  草地 │
石子路   │ 草地  草地  河流  河流  草地 │   石子路
        │ 草地  草地  河流  河流  草地 │
        │ 草地  草地  草地  草地  草地 │
        └───────────────────────────┘
            石子路（边缘装饰带）
```

- **草地**：主地形，占据大部分区域
- **河流**：横贯或纵贯地图，形成天然屏障，分割战场区域
- **石子路**：连接各区域的可行走路径 + 外围装饰带

### 3.4 RuleTile 规则贴图

每个 RuleTile 资产需要 Sprite 贴图用于编辑器画笔预览，以及邻接规则配置：

| 贴图类型 | 数量/地形 | 说明 |
|---|---|---|
| 中心（纯地形） | 1 | 大面积铺设用 |
| 4 方向边缘 | 4 | 与不同地形接壤的边 |
| 4 内拐角 | 4 | 内凹拐角过渡 |
| 4 外拐角 | 4 | 外凸拐角过渡 |
| **小计/地形** | **~13** | |

3 种地形的过渡组合（草↔河、草↔石、河↔石）总计约 **40-50 张 Sprite 贴图**。

> **简化方案**：如果不想画那么多过渡贴图，可以用纯色方块 + RuleTile 只做"填充"不做"过渡"。视觉上是棋盘格拼接效果，同样满足地形多样性目标，贴图只需 3 张。

## 5. 实施步骤

### Step 1: 安装 2D Tilemap 包

通过 `unity_package` 安装 `com.unity.2d.tilemap` 和 `com.unity.2d.tilemap.extras`。

### Step 2: 创建材质

在 `Assets/Materials/Tiles/` 下创建 3 个 URP Lit 材质，颜色对应 3.1 节色值。

### Step 3: 创建 3D Quad Prefab

每种地形创建一个 Quad Prefab：

1. `GameObject.CreatePrimitive(PrimitiveType.Quad)`
2. 旋转 `Euler(90, 0, 0)`（平铺朝上）
3. Scale 设为 `(10, 10, 1)`
4. 赋对应材质
5. 草地/石子路：保留 MeshCollider
6. 河流：移除 MeshCollider（不可行走）
7. 保存为 Prefab 到 `Assets/Prefabs/Tiles/`

### Step 4: 创建 Sprite 贴图

创建 3 张 32×32 像素纯色 PNG（绿/蓝/灰棕），导入设置：Texture Type = Sprite, Pixels Per Unit = 32。

### Step 5: 创建 RuleTile 资产

在 `Assets/Tilemaps/RuleTiles/` 下创建 3 个 RuleTile 资产，每个配置：

- `Default Sprite` = 对应纯色 Sprite（画笔预览用）
- `Default GameObject` = 对应 3D Quad Prefab（实际放置的 3D 物体）

简化版：不配置邻接过渡规则，纯填充式。
完整版：配置邻接过渡规则（草↔河、草↔石、河↔石的边缘和拐角）。

### Step 6: 场景中创建 Tilemap 并画图

1. 场景中创建 Grid + Tilemap GameObject，命名为 `TileGround`
2. 配置 Grid 的 Cell Size = (10, 10, 1)（每格 10×10 单位）
3. 用 Tilemap 画笔画出 12×12 的地图布局（草地为主，河流横贯，石子路连接）
4. 画笔涂格子时，3D Quad 自动出现在场景中

### Step 7: 处理旧 Ground

- 隐藏或删除原 Ground 对象
- 将 NavMeshSurface 组件迁移到 `TileGround` 上
- 配置 NavMeshSurface: `Collect Objects = Children`

### Step 8: NavMesh 烘焙

- 调用 `unity_bake.bake_navmesh` 重新烘焙
- 验证：草地和石子路区域有 NavMesh，河流区域无 NavMesh
- 敌人寻路应自动绕开河流

### Step 9: 验证与测试

| 验证项 | 预期 |
|---|---|
| 3D Quad 渲染正确 | 草地绿、河流蓝、石子路灰棕，位置正确 |
| 河流无 Collider | 河流区域 Quad 无 MeshCollider 组件 |
| NavMesh 连续 | 草地+石子路区域有连续导航网格 |
| NavMesh 河流缺口 | 河流区域无导航网格 |
| 敌人寻路绕行 | 敌人会绕开河流走 |
| 现有场景内容不受影响 | 围墙、树木、建筑、道具位置和功能正常 |
| 编译无错误 | start_compilation_pipeline + console 检查 |

## 6. 运行时动态修改瓦片

Tilemap 永久保留在场景中，支持运行时动态修改：

```csharp
// 运行时在某格放置新瓦片
tilemap.SetTile(cellPosition, riverTile);

// 运行时删除某格瓦片
tilemap.SetTile(cellPosition, null);

// 运行时替换某格瓦片类型
tilemap.SetTile(cellPosition, stonePathTile);
```

Tilemap 会自动销毁旧 Quad Prefab 实例、实例化新 Quad Prefab。可用于：
- 动态开闭河流通道（造桥/拆桥）
- 地形变化事件（草地变岩浆）
- 关卡进度推进改变地图布局

> **NavMesh 动态更新**：运行时修改瓦片后，NavMesh 不会自动更新。如需动态寻路变化，可使用 `NavMesh Obstacle` 组件在河流瓦片上动态雕刻，或重新烘焙局部 NavMesh。

## 7. 风险与注意事项

### 7.1 Static Batching

144 个 Quad 标记为 Static 后，Unity 会自动合并相同材质的 Mesh，Draw Call 预期降至 3-4 个（按材质数量）。如果未标记 Static，Draw Call 会达到 144 个，性能不可接受。

> **注意**：如果后续需要运行时动态修改瓦片，则不能标记 Static（静态合批后无法增删单个 Quad）。需在性能与动态性之间权衡。

### 7.2 Quad 朝向

Quad 默认朝 +Z（竖立），需要旋转 `Euler(90, 0, 0)` 使其平铺朝上。此旋转应烤进 Prefab。

### 7.3 Tilemap 坐标系

`Tilemap.CellToWorld(cell)` 返回的是格子左下角坐标，需要加 `tilemap.tileAnchor` 偏移使 Quad 居中。默认 `tileAnchor = (0.5, 0.5, 0)`。Grid 的 Cell Size 需设为 (10, 10, 1) 以匹配 Quad 的 scale。

### 7.4 河流玩法影响

河流不可行走会改变敌人路径。需要确保：
- 河流不完全封闭玩家所在区域（否则敌人无法到达）
- 河流两侧有石子路/草地桥接，保证路径连通
- Spawner 的生成点不被河流隔离

### 7.5 现有场景内容

- 围墙、树木、建筑等现有场景对象位置不变
- 它们可能站在不同地形的瓦片上（如树在草地、建筑在石子路），这反而是合理的视觉效果
- Quad Y=0 与原 Plane Y=0 一致，现有对象坐标无需调整

### 7.6 瓦片大小与现有对象的匹配

原 Ground scale=12，Plane 默认 10×10 单位 → 实际 120×120。瓦片每片 10×10，12×12=144 片覆盖 120×120，面积一致。现有对象坐标无需调整。

### 7.7 Tilemap 包兼容性

Tuanjie 1.9.3 引擎是否支持 `com.unity.2d.tilemap` 和 `com.unity.2d.tilemap.extras`？需验证。如果不支持 Extras（RuleTile 所在包），可手写一个继承 `TileBase` 的自定义 Tile 类，在 `GetTileData` 中设置 `tileData.gameObject`。

## 9. 开放问题

1. **RuleTile 过渡贴图**：简化版（纯色填充，3 张 Sprite）还是完整版（带过渡边缘，~50 张 Sprite）？简化版视觉是棋盘格拼接，完整版有平滑过渡。
2. **河流形状**：直线横贯？弯曲？十字交叉？影响玩法策略。
3. **石子路分布**：仅外围装饰？还是内部也有路径连接各区域？
4. **水面效果**：纯色蓝即可？还是需要透明/反射效果（可后续用 URP Shader 增强）？
5. **Static Batching vs 运行时动态**：如果需要运行时修改瓦片，不能标记 Static。是否接受 144 Draw Calls？还是用 GPU Instancing / Mesh Combiner 优化？
6. **Tilemap 包兼容性**：Tuanjie 1.9.3 是否支持 `com.unity.2d.tilemap.extras`？如不支持需手写自定义 Tile 类。
